## О проекте

**MagicTech** — полнофункциональная информационная система интернет-магазина аксессуаров для ПК (клавиатуры, мыши, наушники, кабели, кресла и др.) с централизованным каталогом, складом, заказами, биллингом, отзывами и панелью администрирования.

### Что решает

Уходит хаос «Excel + CRM + бумажный склад»: единые остатки, ролевой доступ, аудит критических операций, регламенты резервного копирования и автоматические отчёты.

## Быстрый старт

**Требования:** Python 3.12+, PostgreSQL 16+

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt

copy .env.example .env      # затем заполните секреты в .env (см. раздел «Переменные окружения»)

python manage.py migrate
python manage.py seed_magtech          # ~60 товаров, ~70 заказов, отзывы, возвраты
python manage.py ensure_superuser       # Django Admin: Magic / 123

python manage.py runserver
```

## Функциональные модули

### 📦 Каталог товаров

| Возможность | Описание |
|-------------|----------|
| **Дерево категорий** | До 3 уровней вложенности, кеширование |
| **Карточка товара** | Характеристики (JSON), изображения, SEO-поля, рейтинг, отзывы |
| **Полнотекстовый поиск** | PostgreSQL `tsvector` + морфология (russian), GIN-индекс |
| **Динамические фильтры** | По брендам, цене, наличию, характеристикам — фасеты считаются на лету |
| **Сортировки** | По популярности, новизне, цене (↑↓), рейтингу |
| **«С этим также покупают»** | На основе совместных покупок из заказов |
| **Управление ценами** | Версионирование: старая цена закрывается, новая — с датой и автором |
| **Акции** | На товары / категории / бренды, процент или фиксированная сумма |

### 🛒 Корзина и оформление

| Возможность | Описание |
|-------------|----------|
| **Серверная проверка остатка** | При добавлении товара |
| **Резервирование** | Товар резервируется на 20 минут (настраивается) |
| **Промокоды** | `MAGIC500` (−500 ₽ от 5000 ₽), `GAMER15` (−15 % от 2 товаров) |
| **Автоакции** | −10 % на мыши (по категории) |
| **Комбинирование скидок** | Промокод суммируется с акцией (`is_stackable`) или берётся максимальная |
| **Минимальный заказ** | 300 ₽ (настраивается) |
| **Оформление** | Атомарно: заказ + резерв + платёж + уведомление, полный откат при ошибке |

### 📋 Заказы

| Возможность | Описание |
|-------------|----------|
| **Статус-флоу** | NEW → PAID → CONFIRMED → ASSEMBLY → PACKED → COMPLETED |
| **Отмена** | Снятие резерва, возврат списанного товара, отмена платежа |
| **Переходы по регламенту** | Запрещены перескоки, проверка способа оплаты |
| **Каналы** | Сайт, маркетплейс, мобильное приложение |
| **Нало** | Оплата при получении — отметка администратором |
| **Накладные и ярлыки** | PDF: товарная накладная + ярлык на коробку со штрихкодом |
| **Массовые операции** | Изменение статусов, экспорт в CSV |

### 🏭 Склад

| Возможность | Описание |
|-------------|----------|
| **Приход** | Со сверкой фактического количества с накладной |
| **Корректировка** | С подтверждением и причиной, запрет отрицательного остатка |
| **Списание при сборке** | Автоматическое списание + снятие резерва |
| **Журнал движений** | Приход, списание, резерв, возврат, брак — с документом и автором |
| **Сборка заказов** | Карточка сборки с отметкой позиций |
| **Возврат на склад** | При отмене заказа |

### 💳 Платежи и финансы

| Возможность | Описание |
|-------------|----------|
| **ЮKassa (имитация)** | Подписанный веб-хук (HMAC-SHA256), идемпотентность |
| **Ручное подтверждение** | Fallback при потере веб-хука |
| **Возвраты денег** | Полные и частичные с учётом комиссии шлюза |
| **Сверка с выпиской** | Импорт CSV/XLSX, автосопоставление по номеру заказа и сумме |
| **Финансовый отчёт** | Начислено, оплачено, возвраты, комиссии, нетто по провайдерам |

### 🔄 Возвраты

| Возможность | Описание |
|-------------|----------|
| **Статус-флоу** | NEW → IN_REVIEW → APPROVED/REJECTED → RETURNED_TO_WAREHOUSE → REFUNDED/REPLACED |
| **Возврат с сайта** | Покупатель создаёт заявку на завершённый заказ |
| **Возврат на склад** | Годный — на остаток, бракованный — списывается |
| **Автоматический возврат денег** | При статусе REFUNDED |
| **Аудиторская правка** | После одобрения заявка блокируется, правка с причиной и версией |

### ⭐ Отзывы и вопросы

| Возможность | Описание |
|-------------|----------|
| **Только купившим** | Проверка по завершённому заказу |
| **Премодерация** | pending → approved / rejected |
| **Ответ продавца** | С датой |
| **Пересчёт рейтинга** | Атомарный, при каждом изменении статуса отзыва |
| **Вопросы о товаре** | Без рейтинга, не ограничены «купил» |

### 📊 Отчёты

| Отчёт | Метрики |
|-------|---------|
| **Продажи по периодам** | Выручка, кол-во заказов, средний чек (день/неделя/месяц) |
| **ТОП товаров** | Выручка, маржа, кол-во, возвраты |
| **Финансовый** | Начислено, оплачено, возвраты, комиссии, нетто |
| **Статусы заказов** | В работе, собрано, завершено, задержанные, просроченные |
| **Остатки и оборачиваемость** | Остаток, резерв, продано, оборачиваемость (дни), неликвид |

### 🔐 RBAC (ролевой доступ)

**Роли:**

| Роль | Код | Описание |
|------|-----|----------|
| Администратор | `ADMIN` | Полный доступ |
| Администратор БД | `DB_ADMIN` | Бэкапы, restore, регламентные задания |
| Товаровед | `MERCHANDISER` | Каталог, характеристики, отзывы |
| Бухгалтер | `ACCOUNTANT` | Платежи, возвраты, отчёты |
| Сборщик | `PICKER` | Склад, сборка заказов |
| Покупатель | `CUSTOMER` | Витрина, ЛК |

**Матрица разрешений** — `users/permissions.py`. Проверка на сервере в каждом обработчике панели и API (403 + запись в аудит). Не только скрытие кнопок в UI.

| `Alt+T` | Переключить тему |
| `Alt+/` | Фокус в поиск списка |
| `Alt+H` | Справка по клавишам |
| `/` | Фокус в поиск (одиночная) |
| `?` | Справка (одиночная) |

## Команды Django

| Команда | Описание |
|---------|----------|
| `python manage.py seed_magtech [--orders N]` | Демо-данные: пользователи, каталог (~60 товаров), заказы (~80), акции, промокоды, отзывы, возвраты. Идемпотентна. |
| `python manage.py ensure_superuser` | Создать суперпользователя для Django Admin (Magic / 123) |
| `python manage.py sync_sequences` | Синхронизация PostgreSQL-последовательностей с реальными max(id) |
| `python manage.py run_scheduled_jobs` | Планировщик: раз в минуту выполняет cron-задания (снятие резервов, бэкапы, VACUUM, архивация) |
| `python manage.py generate_products --count N` | Генерация тестовых товаров (для нагрузочных тестов) |
| `python manage.py benchmark_catalog` | Замер производительности каталога и поиска |
| `python manage.py load_test --orders N` | Нагрузочное тестирование: N параллельных оформлений |
| `python manage.py release_reservations` | Снять просроченные резервы корзин |

## Переменные окружения

Секреты **не имеют значений по умолчанию в коде** — приложение не запустится без них.
Локально: скопируйте `.env.example` в `.env` и заполните значения (файл `.env` в `.gitignore`).
Боевой контур: задавайте переменные окружения процесса.

```powershell
copy .env.example .env
python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"   # DJANGO_SECRET_KEY
python -c "import secrets; print(secrets.token_hex(32))"                                       # YOOKASSA_WEBHOOK_SECRET
```

| Переменная | Обязательная | По умолчанию | Описание |
|-----------|--------------|--------------|----------|
| `DJANGO_SECRET_KEY` | **да** | — | Секретный ключ Django (генерировать, не коммитить) |
| `DB_NAME` | **да** | — | Имя базы данных |
| `DB_USER` | **да** | — | Пользователь БД |
| `DB_PASSWORD` | **да** | — | Пароль БД |
| `YOOKASSA_WEBHOOK_SECRET` | **да** | — | Ключ HMAC-SHA256 подписи веб-хуков |
| `DB_HOST` | нет | `localhost` | Хост БД |
| `DB_PORT` | нет | `5432` | Порт БД |
| `DB_SSL_MODE` | нет | `prefer` | `prefer` / `require` / `verify-full` (production — `require`) |
| `DJANGO_DEBUG` | нет | `1` | Режим отладки (production — `0`) |
| `DJANGO_ALLOWED_HOSTS` | нет | `127.0.0.1` при DEBUG, иначе пусто | Разрешённые Host через запятую |
| `REDIS_URL` | нет | — | URL Redis для кэша |
| `MAGTECH_BACKUP_DIR` | нет | `./backups` | Каталог бэкапов |
| `PG_BIN` | нет | PATH | Путь к утилитам PostgreSQL |

## Регламентные задания

Планировщик `python manage.py run_scheduled_jobs` запускается раз в минуту (cron / Windows Task Scheduler):

| Задание | Расписание |
|---------|-----------|
| Снятие просроченных резервов | Каждые 5 минут |
| Полный бэкап БД | Ежедневно 02:00 |
| Инкрементальный бэкап | Каждые 4 часа |
| Бэкап схемы и справочников | Еженедельно, при релизе |
| VACUUM ANALYZE | Ежедневно 03:30 |
| Ротация копий (30 дней) | Ежедневно 06:00 |
| Проверка restore | Ежемесячно |
| Архивация заказов (365 дней) | Ежемесячно |

## Безопасность

- **Пароли** — Argon2 с прозрачным переходом от bcrypt/PBKDF2
- **Сессии** — 8 часов, HttpOnly, SameSite=Lax
- **CSRF** — защита всех POST-форм
- **XSS** — экранирование, `X-Frame-Options: DENY`, `Content-Type-Nosniff`
- **SQL-инъекции** — ORM-параметры, защита от параметризованных запросов
- **RBAC** — серверная проверка в каждом обработчике панели и API
- **Аудит** — каждая критическая операция записывается с IP и User-Agent
- **HTTPS** — сессии только по защищённому каналю в production
