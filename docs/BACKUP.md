# Регламент резервного копирования и восстановления

| Требование ТЗ | Реализация |
|---------------|-----------|
| Полный бэкап — ежедневно в ночное окно | задание `backup-full` (02:00) → `pg_dump -Fc`; ОС: `scripts/backup_full.sh` / `.ps1` |
| Инкрементальный — каждые 4 часа | задание `backup-incremental` (транзакционные таблицы); физический — `scripts/backup_incremental.sh` (`pg_basebackup --incremental`, PostgreSQL 17+) |
| Справочники и конфигурации — при изменении схемы/релизе | задание `backup-schema` (схема + справочники) + запуск вручную перед `migrate` |
| Хранение ≥ 30 дней | задание `cleanup-backups`; последняя проверенная полная копия не удаляется никогда |
| Проверка restore ≥ 1 раз в месяц на тестовом контуре | задание `verify-restore`: контрольная сумма SHA-256, `pg_restore --list`, восстановление в `MagicTech_restore_test`, подсчёт таблиц |
| RPO ≤ 15 минут | архив WAL: `scripts/postgresql-wal.conf` (`archive_timeout = 900`) |
| RTO ≤ 1 час | восстановление логической копии: минуты для БД до нескольких ГБ (замер выводит `restore.sh`) |

## Процедура восстановления (демонстрация на защите)
1. Создать копию: панель → «Бэкапы» → «Полная» (или `scripts/backup_full.sh`).
2. Симулировать порчу: например, `DELETE FROM reviews;` в pgAdmin или удалить товар в панели.
3. Проверить копию: «Проверить restore» — восстановление в `MagicTech_restore_test` без влияния на рабочую БД.
4. Восстановить: «Восстановить…» (роль «Администратор БД», ввод имени БД + подтверждение) или
   `TARGET_DB=MagicTech scripts/restore.sh backups/<файл>.dump`. Восстановление идёт одной транзакцией
   (`--single-transaction`): при ошибке рабочая БД остаётся прежней.
5. Убедиться, что данные вернулись; в аудите — записи `restore_started` / `restore_ok`.

## Point-in-time recovery (RPO ≤ 15 мин)
При включённом архиве WAL: восстановить последнюю физическую копию (`pg_combinebackup` для цепочки
инкрементов), задать `restore_command` и `recovery_target_time` в `postgresql.conf`, создать `recovery.signal`, запустить СУБД.

## Права
Бэкапы создаёт роль с правом `db.backup` (Администратор, Администратор БД), восстановление рабочей БД —
только `db.restore` (Администратор БД). Каждое обращение к контуру БД фиксируется в аудите (`db_access`);
вне режима разработки контур доступен только по HTTPS.
